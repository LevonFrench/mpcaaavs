# Asset pack manifest (`mpcaaavs-assets` v1)

Status: implemented in `visualizer/src/asset-packs/`, checked by `visualizer/tools/check-asset-packs.mjs`.

Show plates (see `SPRITE-SHOW-KIT.md`) may use sprite art from private local asset packs. A pack is a directory
`show-assets-private/<pack-id>/` holding one `pack.json` and PNG atlases. The public build ships no pack: every plate that
uses a pack also draws a procedural **stand-in**, so the build works with no private files. This document defines the pack
format, the loader and the stand-in API.

## Legal and privacy rules

- Packs are local only. `show-assets-private/` is git-ignored at the repository root and under `visualizer/`; it is never
  committed, mirrored or packaged. `tools/package-release.py` refuses any path containing a `show-assets-private` segment and
  `tools/check-release-package.py` proves it.
- Manifests carry a **neutral** `name` ("Fixture Pack", never a franchise title or logo text). Real titles appear only through
  the private local title overlay. Regions, clips and tags use neutral genre-level ids.
- Pixels never live in the manifest, and the repository never contains pack art. Test fixtures are tiny synthetic PNGs
  generated by arithmetic (`visualizer/tools/fixtures-asset-pack.mjs`).

## Where a pack lives and how it is read

```
show-assets-private/<pack-id>/
  pack.json
  atlas/<name>.png
```

The hosts read packs next to the page that runs them, through the same local-file route as the preset collection
(`avs presets/`): the MPC host maps `visualizer/` to `https://aaavs.invalid/` (WebView2 virtual host) and the standalone Player
serves `visualizer/` (`tools/serve.mjs`). So the installed location is `visualizer/show-assets-private/<pack-id>/`; on a
development machine, copy or link the extraction output there (the MPC host follows links; the Player's library server refuses them, so copy). `fetchPackSource(packId)` (`source.ts`) is the MPC host's production
adapter (the Player reads through its library server, see "Host wiring"): it builds `./show-assets-private/<pack-id>/<path>` against the page URL and reads it with the bounded reader of
`avs/local-assets.ts`. A 404 means "not installed". Hosts never duplicate pack logic; they only differ in how the folder is
served. `memoryPackSource` (tests, generated packs) and `tools/asset-pack-fs-source.mjs` (Node tools and checks) implement the
same `AssetPackSource` contract.

Validate a pack from a shell: `node tools/validate-asset-pack.mjs show-assets-private/<pack-id>` (from `visualizer/`).

## Paths

Every file name in a manifest, and every path an adapter is asked to read, is a pack-relative path validated by an
**allowlist**: 1-6 segments of at most 64 characters, each made of ASCII letters, digits, `_`, `-` and `.`, starting with a
letter, digit or `_`, not ending with a dot, at most 128 characters in total. That one rule rejects `..` and `.` segments, absolute
paths, backslashes, drive letters and URL schemes (`:`), percent-encoding (`%`), empty segments, control and bidi characters,
non-ASCII look-alikes, hidden files, trailing-dot and trailing-space aliases, 8.3 short names (`~`), NTFS stream syntax and
Windows device names (`con`, `nul`, `com1`...). Atlas files must end in `.png`. Pack ids are 1-48 characters of `a-z`, `0-9`,
`-`. Adapters re-validate (defence in depth) and additionally refuse symlinks (Node) and any URL that resolves outside the pack
directory (fetch).

## Manifest

The manifest is JSON, at most 512 KiB, UTF-8. Validation is strict and data-only: unknown keys, wrong types, non-integer
pixels, out-of-range numbers, rectangles outside their atlas, duplicate ids, unresolved references and bad paths are errors
with a dotted path (`regions.hero.rect[0]`). On success the result is normalized (all defaults filled in) and deeply frozen.
Rectangles are `[x, y, width, height]` in atlas pixels, points are `[x, y]` inside their region.

```jsonc
{
  "format": "mpcaaavs-assets",          // required, exact
  "version": 1,                         // required, exact; newer versions are rejected
  "id": "fixture-pack",                 // must equal the directory name
  "name": "Fixture Pack (synthetic)",   // neutral display name, 1-48 characters
  "atlases":  { "sprites": { "file": "atlas/sprites.png", "width": 64, "height": 64, "filter": "nearest" } },
  "palettes": { "main": { "colors": ["#102030", "#405060"], "cycles": [{ "from": 0, "to": 1, "beats": 2 }] } },
  "regions":  { "hero": { "role": "actor", "atlas": "sprites", "rect": [0, 16, 16, 24], "class": "hero", "clips": { "idle": "hero-idle" } } },
  "clips":    { "hero-idle": { "verb": "idle", "loop": true, "hold": [6, 6, 6, 6], "strip": { "atlas": "sprites", "rect": [0, 0, 64, 16], "count": 4 } } },
  "fonts":    { "digits": { "atlas": "ui", "rect": [0, 0, 30, 16], "cell": [6, 8], "columns": 5, "chars": "0123456789" } }
}
```

### Atlases

`file` (path, `.png`), `width` and `height` (1-4096, must equal the PNG's real size; the loader compares the PNG header, including
its CRC), `filter` (`nearest` default, or `linear`). At most 16 atlases, 8 MiB each, 32 MiB per pack. Atlases are 8-bit or 16-bit
PNG of any colour type; decoding is the host's (`createImageBitmap`). A pack can be loaded without a decoder ("metadata only");
plates then draw stand-ins.

### Palettes

`colors`: 1-256 entries `#rrggbb` or `#rrggbbaa`. `cycles`: up to 8 of `{from, to, beats}`: palette indices `from..to` rotate one
full turn per `beats` beats (0.25-64), in whole steps, as colour-cycled backgrounds do. `paletteColorsAt(palette, beat)` is a pure
function of the beat, so a seek lands on the same colours. A region, clip or font may name a `palette`.

### Regions and roles

Every region has `role`, `atlas`, `rect`, optional `anchor` (inside the region; defaults: bottom-centre for `actor`, `prop`,
`pickup`; centre for `projectile`, `effect`; top-left otherwise), optional `palette`, up to 8 `tags` (`a-z0-9-`) and, on `hud`,
`text` and `screen` only, a `nineSlice` `{left, top, right, bottom}` (nine-slice margins in region pixels) that must leave a centre row and column. The roles
are those of `SPRITE-SHOW-KIT.md`:

| Role | Extra fields |
| --- | --- |
| `actor` | `class` (`hero`, `enemy`, `boss`, `npc`, `companion`; required), `size` (`tiny`..`huge`, default `medium`), `facing` (`left`, `right`, default `right`), `clips`: verb to clip id (each clip's own `verb` must match) |
| `clip` | none: a bare animation frame cell, referenced by a clip's `frames` |
| `projectile` | `motion` (required), `spawn` offset from the actor, `clip`, `impact` (an `effect` region) |
| `effect` | `blend` (`normal`, `add`, `screen`), `duration` in source frames (default 12), `scale` (size class), `clip` |
| `pickup` | `idle` (clip), `collect` (an `effect` region), `caption` (1-24 plain characters) |
| `prop` | `idle` (clip), `break` (clip), `drops` (up to 16 `pickup` regions) |
| `background` | `scroll` factor 0-4 (default 1), `layer` 0-15, `loopWidth`, `tiles` (animated-tile clip) |
| `hud` | `part` (`bar`, `counter`, `digits`, `box`, `emblem`, `banner`, `cursor`; default `box`), `fill` direction (`left-to-right`, `right-to-left`, `bottom-to-top`, `top-to-bottom`), `segmentPitch`, `ghost` colour |
| `text` | none beyond the common fields (dialogue boxes, name plates; use `nineSlice`) |
| `transition` | `beats` (0.25-64, default 1), `direction` (`in`, `out`, `left`, `right`, `up`, `down`), `clip` |
| `screen` | `slots`: named rectangles inside the region, `cursors`: points inside the region (up to 32 each) |

Motion models: `straight`, `arc`, `sine`, `boomerang`, `homing`, `bounce`, `spread`, `orbit`, `fall`, `rise`, `swoop`, `hover`,
`pendulum`. Clip verbs: `idle`, `walk`, `run`, `dash`, `jump`, `fall`, `crouch`, `attack`, `special`, `super`, `cast`, `throw`,
`guard`, `parry`, `hurt`, `knockdown`, `die`, `spawn`, `enter`, `exit`, `taunt`, `pose`, `transform`, `swim`, `climb`, `hang`,
`swing`. The manifest describes timing and metadata only; motion is computed by plates as a function of media time.

### Clips (animation strips)

`verb`, `loop` (default false), `hold` (source frames each frame is shown: one integer for all, or one per frame, 1-600; default
4), `big` (frame indices where the release, impact or flash lands, up to 8), optional per-frame `anchors`, optional `palette`, and
exactly one frame source:

- `frames`: region ids (up to 256), each frame using its region's rectangle and anchor, or
- `strip`: `{atlas, rect, count, axis}`, `count` equal cells along `axis` (`x` default, or `y`); `count` must divide the strip evenly.
  Frame anchors default to bottom-centre of the cell.

Loops wrap; one-shots hold their last frame. Stand-in and real art share the same timeline: plates pass `time` in source frames.

### Fonts (glyph grids)

`atlas`, `rect`, `cell` `[w, h]`, `columns`, `chars` (glyphs in grid order, left to right then down; no repeats, no control
characters), `advance` (one integer or one per glyph; default cell width), `lineHeight`, `baseline`, `role` (`hud` or `text`).
The grid must fit in `rect`.

### Limits

Up to 4096 regions, 2048 clips, 16 fonts, 16 palettes, 256 glyphs per font. Validation reports at most 64 issues. The authoritative
numbers are `ASSET_PACK_LIMITS` in `manifest.ts`.

## Loading

```ts
import { fetchPackSource, loadAssetPack } from './asset-packs/index.ts';
const result = await loadAssetPack(fetchPackSource('my-pack'));   // never throws
const pack = result.pack;                                          // AssetPack | null
```

`loadAssetPack` returns `status: 'loaded'`, `'absent'` (no manifest: not installed or unreadable) or `'invalid'` (with `issues`).
A pack with any bad manifest entry, missing or mis-sized atlas, or undecodable atlas is `invalid` as a whole and never partly used.
`loadAssetPackOrNull` returns the pack or `null`. Load a pack once per session, off the frame path.

Typed lookups on `AssetPack`: `region(id)`, `regionOf(id, role)` (undefined unless the role matches), `idsByRole(role)` (sorted, a
stable order for seeded picks), `clip(id)`, `clipFrames(id)` (resolved rectangles, anchors, holds), `actorClip(actorId, verb)`,
`font(id)`, `palette(id)`, `atlas(id)`, `image(atlas)`. Lookups of names a pack does not define (including `constructor`) return
`undefined`.

## Host wiring (per-device setting, both hosts, workers)

Status: implemented in `visualizer/src/show/pack-setting.ts`, `pack-host.ts`, `pack-registry.ts`, the `show-pack` message of
`src/show/protocol.ts` and, for the Player, `visualizer/tools/show-pack-server.mjs`; checked by `tools/check-show-pack-host.mjs`
(CPU only: plumbing with fake sources and a real loopback HTTP server, no browser, GPU or pixels).

**The setting names a pack, never a path.** The device-local setting is a pack id (`a-z0-9-`, at most 48 characters). It is read from the
page URL (`?pack=<id>`, for testing; `?pack=off` or an empty value selects none even when a value is stored) and otherwise from localStorage
`mpcaaavs.showPack` (the same device-local place as `mpcaaavs.nervEngine`; `writeShowPackSetting(id | null)` stores or clears it). The default is
no pack. An invalid id fails closed (no pack, no fallback). The MPC host navigates to a fixed URL, so there the localStorage value is the way to
set it (WebView2 dev tools: `localStorage.setItem('mpcaaavs.showPack', 'my-pack')`); no native wire field or registry value is involved.

**One provider, two transports.** `src/mpc-host.ts` (shared by the MPC host and the Player) creates `window.aaavsShowPacks`, a `ShowPackProvider`
(unless the page already published one, exactly like `window.aaavsSongMap`). The provider resolves the setting, loads the pack once through
`loadAssetPack` and keeps the bytes it validated. Hosts differ only in the `AssetPackSource`:

| Host | Source | Where the files come from |
| --- | --- | --- |
| MPC-HC (WebView2) | `fetchPackSource(id)` | `visualizer/show-assets-private/<id>/` beside the page, fetched same-origin through the `https://aaavs.invalid/` virtual host mapping (already git-ignored, never packaged). **No native change is needed.** |
| Standalone Player | `httpPackSource(id)` | the loopback library server, read-only, from a directory chosen on the server side (below) |

**Player server side.** `createLibraryHandler(root, { showPacks })` (`tools/standalone-library.mjs`, reader in `tools/show-pack-server.mjs`) adds
three read-only operations to `POST /api/aaavs/library`, behind the existing same-origin loopback check and independent of the preset collection
and its write queue:

- `{op: 'list-show-packs'}` answers `{type: 'show-packs', packs: [{id}]}`: directories of the configured folder with a regular `pack.json`.
- `{op: 'list-show-pack-files', pack}` answers `{type: 'show-pack-files', pack, files: [{path, bytes}]}`: `pack.json` and `.png` files only.
- `{op: 'read-show-pack-file', pack, path}` answers the raw bytes (`application/octet-stream`); errors are the usual JSON `library-error`
  (`404` with `missing: true` when the file is not there, `400` for a refusal).

The directory is configured by whoever starts the server, never by the page: `node tools/serve.mjs --show-packs <dir>`, else the environment
variable `AAAVS_SHOW_PACKS`, else the conventional `visualizer/show-assets-private/` when it exists. `<dir>/<pack-id>/pack.json` and
`<dir>/<pack-id>/atlas/<name>.png` are the layout. Without a configured directory every operation is refused ("Show packs are not configured").
The page can only send a pack id and a pack-relative path, both validated with the allowlist of `asset-packs/paths.ts` (the server carries a
mirrored copy, and the check proves the two agree on a hostile corpus). Only `pack.json` (at most 512 KiB) and `.png` files (at most 8 MiB each)
are ever served; anything else is refused, including every other file in the pack folder. Symbolic links are refused at every level below the
configured directory, the pack directory itself must not be one, only regular files are read, the real location must equal the spelling, reads
open with `O_NOFOLLOW` where the platform has it, sizes are checked before and on the open handle, and listings are bounded (64 packs, 256
files). The configured directory itself may be a link the owner chose.

**Workers.** The host attaches the provider to each scene worker it starts for the show engine (`show-render.worker.js` only; other workers never
see a pack): `ShowPackProvider.attach(worker)` posts, once the pack is loaded, `{type: 'show-pack', generation, packId, manifest, atlases}`
(`ShowPackMessage`): `pack.json` exactly as read and each atlas's PNG bytes by atlas id, as transferable copies. Nothing is posted for a pack that
is off, absent or invalid. The worker (`src/show-render.worker.ts`, one hook line ahead of its generation gate, because a pack belongs to the
host and not to a show generation) calls `receiveShowPack`, which re-validates the pack with `loadAssetPack` over an in-memory source (manifest,
PNG headers against declared sizes, decode with `createImageBitmap`) and stores the result in `src/show/pack-registry.ts`. A plate reads
`getShowPack()` and passes it to `drawSprite` / `drawGlyphs`: `null` (nothing sent, absent, invalid, cleared, or still decoding) means stand-ins,
so plates never branch on it. A failed validation empties the registry (no half-used pack); the last message wins. `validateShowRequest` bounds
the message: a valid id, a manifest of at most 512 KiB, at most 16 atlases of at most 8 MiB each and 32 MiB in total, plain `ArrayBuffer`s.

Native additions: none. The MPC host needs no new bridge message, registry value or virtual host mapping (it already serves `visualizer/`), and the
setting is page-local, so nothing is added to the native wire.

Costs to know: the pack bytes are posted to every show worker the host starts (a scene change starts a worker), so a large pack is copied and
decoded per scene; plates draw stand-ins until their worker has decoded it. Not done: changing the setting at run time (reload the page), and
ImageBitmap transfer (workers decode the PNG bytes themselves).

## Procedural stand-ins

A plate declares a `SpriteSlot` (`region` id, expected `role`, design `size`, optional `tone` and `anchor`) and calls
`drawSprite(ctx, pack, slot, x, y, options)` with the pack or `null`. It draws the real region when the pack has that id with that
role and a decoded atlas, and otherwise draws a stand-in of the same size, anchor and timing from plain shapes (figure, diamond,
starburst, gem, crate, banded backdrop, meter, text box, wipe, menu grid) in the slot's tone. `drawGlyphs` does the same for text
(procedural block font). Stand-ins are pure functions of (slot, time, options): no clock, no randomness, no game art. A plate never
branches on whether a pack exists, and a metadata-only pack, an invalid pack, a missing region and a wrong-role region all
behave exactly like no pack for that slot. `example-plate.ts` is a complete small plate on this API; `drawNineSlice` and
`spriteSource` are exposed for plates that need them.

## Checks

`npm run check` runs `tools/check-asset-packs.mjs`: good and bad manifests (every rule above), path rejection on every adapter,
loader outcomes (absent, invalid, loaded, metadata only), the stand-in path (no pack, invalid pack, wrong role, hostile options,
determinism, no clock or randomness), and the repository rules (git-ignore, nothing tracked). `tools/check-release-package.py`
proves release packaging never includes `show-assets-private/`.
